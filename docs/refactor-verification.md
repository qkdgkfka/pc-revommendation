# 리팩토링 검증 보고서 · 2026-10-01

승인된 계획을 현재 작업 폴더에 구현했다. 기존 디자인과 추천·가격·FPS 계산 기준을 유지하고, 배포 및 데이터 갱신 스크립트는 실행하지 않았다. 작업 전부터 수정되어 있던 DB와 벤치마크 JSON은 시작 시점의 SHA256과 일치한다. Git에 보이는 두 데이터 파일의 변경은 기존 사용자 변경이다.

## 구현

- `server_fixed.py`는 330줄의 호환 진입점으로 남기고 HTTP, 판매처, DB, 가격, 추천, FPS를 `pcbuilder/`로 분리했다. 기존 HTTP 경로, 요청·응답 필드, 구매 URL 별칭과 DDR 필드를 유지했다.
- 서버와 크롤러의 파싱을 `product_parsing.py`, `retailer_parsing.py`로 통합했다. 입력별 차이는 회귀 검사로 보존했다. 기존 입력 887개를 비교한 결과가 일치했다.
- React 18.3.1과 Vite를 잠금 파일로 고정했다. `src/`의 화면, 상태 저장소, 요청 관리, 순수 계산으로 분리하고 전역 상태·숨겨진 select·이중 렌더러·구형 GPU 선택기를 제거했다. 추천 화면과 그래픽 상세를 지연 로드한다.
- 카테고리별 검색어와 입력 중인 초안, 화면별 입력, 선택 SKU를 보존한다. 동일 요청 공유, 취소와 응답 버전 검사를 적용했다. 저장된 제품을 판매처 조회 전에 표시하지 않는다. 실패 후 재시도는 실제 재조회를 수행한다.
- 빌드 JS/CSS와 Pretendard에 해시 파일명 및 장기 캐시를 적용했다. HTML은 재검증한다. 텍스트 자산은 사전 gzip을 사용하고, JSON도 압축한다. 게임 아이콘 41개는 바이트 변경 없이 `public/assets/game-icons/`로 옮겼으며 기존 URL과 갱신 도구를 유지했다.
- 카탈로그·필터, 사진과 동일 조건 FPS를 재사용한다. DB/WAL·스냅샷·설정 변경과 가격 만료 경계를 반영한다. 동시 데이터 변경 중 계산한 추천을 새 버전의 캐시에 넣지 않는다.
- 판매처 페이지 조회는 전체 12초 기한과 남은 시간을 사용한다. 페이지 크기 50개, 커서와 SKU 중복 제거를 유지한다. 취소·시간 초과·판매처 오류·빈 결과를 구분한다.
- HTTP FPS·추천은 예측 DB를 저장하지 않는다. 별도 사전 계산 스크립트만 명시적으로 저장한다. 미사용 함수 19개, 연결되지 않은 가져오기 처리, 구형 JS/React 번들과 분석용 일회성 스크립트 3개를 제거했다. 모델 산출물은 보존했다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| Python 전체 회귀 검사 | 199개 통과 |
| ES 모듈 기반 Node 검사 | 기존 32개 포함 45개 통과 |
| Vite 운영 빌드 | 성공, gzip 파일 생성 |
| 운영 HTTP | gzip, Content-Length, ETag/304, 캐시 구분, 폰트 MIME 확인 |
| 빌드 없음/빈 빌드 폴더 | API 정상, 웹에는 빌드 안내 |
| 보호 데이터 | DB·벤치마크 SHA256 동일 |
| 독립 코드 리뷰 | 주요 지적 4건 수정, 최종 중요 지적 없음 |

Chrome에서 1440×1000, 390×844를 확인했다. 추천·추천 가져오기, 9개 부품 종류, 검색·필터·정렬·더 보기, 선택·해제·전체 비우기, 소켓 경고, FPS·작업·그래픽 상세를 검증했다. 빠른 연속 검색, 늦은 응답 무시, 초기화, 화면 입력 보존, 판매처 실패·재시도·시간 초과·빈 결과도 확인했다. 키보드 게임 선택과 견적 스크롤, 모바일 고정 버튼, 가로 넘침을 검사했으며 페이지/콘솔 오류는 없었다. Browser 플러그인이 없어 Playwright와 설치된 Chrome을 사용했다.

브라우저의 반복 가능한 동작 검사는 고정 API 응답을 사용했다. 운영 서버의 실제 카탈로그·FPS API와 판매처 읽기 전용 조회는 별도로 검증했다. 다나와는 CPU 3개를 반환했고 컴퓨존은 해당 검색에 빈 결과를 정상 반환했다. 이 조회는 저장하지 않았으며 전체 실시간 추천 가격을 새로 수집한 검증은 아니다.

처음 실패하던 Python 계산 테스트는 운영 자료에서 빠진 보정 데이터를 요구했다. 검토된 고정 자료를 `tests/fixtures/`로 분리했고, 실제 보정 자료가 없을 때 지원하지 않는 값을 만들지 않는 검사도 추가했다. Python 실행 도구는 변경 가능한 데이터를 임시 폴더에 복사한다.

## 동일 조건 성능 비교

초기 화면의 JS/CSS만 비교하며 HTML·이미지·폰트는 전송량 목표에서 제외했다. 이전 코드의 실제 파일과 최종 Python 서버의 gzip 응답을 비교했다. 캐시가 비어 있는 첫 방문 기준이다.

| 항목 | 변경 전 | 변경 후 | 결과 |
|---|---:|---:|---|
| 초기 JS/CSS 원본 | 387,488 B | 260,886 B | 32.7% 감소 |
| 초기 JS/CSS gzip 전송 | 113,896 B | 83,119 B | **27.0% 감소** · 목표 25% 달성 |
| 초기 JS/CSS 파일 요청 | 13개 | 2개 | 추천·상세 파일은 사용 시 조회 |
| 카탈로그 반복 처리 중앙값 | 194.685 ms | 4.013 ms | **97.9% 감소** · 목표 50% 달성 |
| 카탈로그 첫 처리 | 839.342 ms | 845.729 ms | 첫 계산 비용은 비슷함 |

카탈로그는 동일 DB·JSON·시장 캐시를 사용해 10회 측정했다. 전후 JSON의 SHA256이 일치한다. 운영 HTTP에서는 반복 카탈로그 중앙값 0.958ms, 첫 FPS 22.179ms, 반복 FPS 중앙값 1.167ms였다. 이는 로컬 측정이며 네트워크나 실제 판매처 지연을 나타내지 않는다.

검색·추천은 같은 확인가 후보와 판매처당 20ms의 고정 지연을 사용했다. 첫 계산은 별도 프로세스 3회 중앙값, 반복은 10회 중앙값이다. 이전 코드의 예측 저장도 임시 DB로 격리했다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 검색 첫 처리 | 33.750 ms | 31.259 ms |
| 검색 반복 처리 | 0.065 ms | 0.072 ms |
| 추천 첫 처리 | 109.212 ms | 114.895 ms |
| 추천 반복 처리 | 1.010 ms | 2.529 ms |
| 검색 11회에 대한 판매처 작업 | 2회 | 2회 |
| 추천 11회에 대한 후보 조회 | 1회 | 1회 |

이 작은 추천 자료에서는 버전·만료 검사와 독립 응답 복사 비용으로 처리 시간이 소폭 증가했다. 검색·추천 전체 지연의 일괄 감소를 주장하지 않는다. LOW/MID/HIGH 부품, 합계와 높음 옵션 FPS는 전후 모두 일치했다. 별도 동시성 검사에서는 같은 판매처 조회 2개가 1개 작업을 공유하며, 다른 조건은 독립적으로 진행했다. 반복 페이지가 판매처 기한을 넘기지 않는 검사도 통과했다.

측정 원본은 `docs/refactor-metrics.json`에 저장했다. 재현 도구는 `scripts/benchmark_catalog.py`, `scripts/benchmark_requests.py`, `scripts/verify_http.py`이며 이전 코드 폴더를 `--project`로 지정할 수 있다.

## 실행

```sh
npm ci
npm run build
python3 server_fixed.py --port 4000
```

개발 시 Python API를 실행한 뒤 `npm run dev`를 사용한다. 검증은 `python3 scripts/run_python_tests.py`, `npm test`, 운영 서버를 실행한 상태에서 `FRONTEND_URL=http://127.0.0.1:4000 npm run test:browser`로 실행한다. 새 배포는 수행하지 않았다.
