# 검증 상품 수집 및 저장

프로젝트 폴더에서 실행:

```powershell
python scripts/refresh_product_catalog.py --pages 12 --source all --models
```

- 다나와·컴퓨존 CPU/GPU/메인보드/RAM/SSD/파워 페이지와 CPU/GPU 모델별 검색.
- 실제 양수 판매가, 정확한 SKU 및 정상 이미지 응답을 검증한 상품만 SQL 저장.
- 실패한 조회는 이전 저장 자료를 지우거나 확인 시각을 갱신하지 않음.
- 추가 페이지부터 수집: `--start-page 7 --pages 12`.
- 다른 부품군 지정: `--types cpu,gpu,mb,ram,storage,psu,hdd,case`.
- 수집은 수동 실행이며 자동 예약 작업은 설정하지 않음.

## 저장 위치

- `data/pc.db` / `retail_products`: 판매처별 SKU, 상품명, 가격, 상품/사진 URL, 확인 시각, 사양 JSON.
- `data/pc.db` / `retail_price_history`: SKU별 관측 가격 이력.
- `data/product_images/`: URL 해시로 중복 제거한 실제 사진 파일.
- `data/retail_crawl_report.json`: 최근 실행의 수집·검증·누적 저장 수.

기존 components/prices/benchmarks 테이블과 계산식은 유지한다.
저장 상품은 catalog API와 상품 검색의 페이지에 합쳐지며, 판매처·검색어 조건을 따른다.
가격 확인 후 24시간이 지나면 이전 확인가로 표시하고 자동 추천 후보에서 제외한다.
이미지 캐시는 6시간 후 재검증한다. 파일이 없어지거나 이미지 확인에 실패하면 추천하지 않는다.
추천 계산은 알려진 성능·호환성 자료가 있는 검증 상품을 대상으로 한다.
따라서 전체 저장 SKU 수와 한 번의 추천에서 평가하는 대표 후보 수는 다르다.

## 직접 선택 검색·페이지 처리

`/api/products?type=motherboard&page=1&limit=50&source=all`은 최대 50개의
실제 판매처 SKU를 반환한다. 다음 요청은 같은 조건과 응답의 `cursor`를 유지해
`page=2`를 요청한다. CPU/메인보드/RAM/GPU/SSD/파워/HDD에 동일하게 적용된다.
판매처에 상품이 적으면 있는 상품만 반환한다.

예시:

```text
/api/products?type=gpu&series=RTX%2040&maker=asus&sort=price_asc&limit=50
/api/products?type=gpu&series=RX%207000&maker=sapphire&limit=50
/api/products?type=gpu&model=RTX%204070%20SUPER&limit=50
```

- GPU는 `vendor`, `family`, `series`, `chipset`, `manufacturer`로 정규화한다.
  구조화된 칩셋을 우선 사용하고 제품명은 사양이 없는 경우에만 해석한다.
  시리즈 전체와 Ti/SUPER/XT/XTX 등의 정확한 모델 조건을 구분한다.
- 시리즈 버튼은 전체 세대 검색을 실행한다. 모델을 선택하면 정확한 칩셋으로
  좁히며 브랜드·VRAM·판매처·검색어 조건은 유지한다.
- 다나와의 실제 페이지는 최대 40개 그룹, 컴퓨존은 20개 행이다.
  서버는 다음 판매처 페이지를 이어 읽어 50개의 고유 SKU를 채운다.
  그룹 내 용량·패키지 옵션은 별도 SKU로 보존한다.
- 판매처의 세대 검색이 다른 세대까지 반환하거나 AMD `9000`/`7000`을
  정확한 모델 번호로 취급하는 경우, 실제 카탈로그에 있는 해당 세대의
  칩셋 검색을 번갈아 진행한다. 결과는 정규화한 세대·모델로 다시 확인한다.
- 저장된 실제 판매처 상품도 동일한 조건으로 합친다. 저장 가격의 원래
  확인 시각과 이전 확인가 상태를 유지하며 새로운 실시간 가격으로 꾸미지 않는다.
- 판매처+상품 코드로 중복을 제거하고, 검색별 전달 완료 SKU와 페이지를
  저장한다. 같은 페이지 재요청과 다른 검색의 가격 갱신이 기존 커서의
  결과를 이동시키지 않는다. 만료된 커서는 1페이지로 재시작한다.
- 정렬은 검색에서 확보한 상품에 적용한다. 추가 로딩 후에도 프런트엔드가
  전체 로딩 결과를 다시 정렬한다. 아직 읽지 않은 판매처 전체 재고를
  전부 수집해 전역 최저가 순서를 보장하는 기능은 아니다.
- 요청마다 판매처당 최대 6회, 약 12초의 수집 예산을 둔다. 희소 조건이나
  판매처 지연으로 50개를 채우지 못해도 다음 데이터가 있으면 `partial`과
  `has_more`를 표시해 추가 로딩을 허용한다. 없는 상품을 생성하지 않는다.

### 적은 결과가 표시되던 원인

고정된 5개 제한은 없었다. 기존 흐름은 프런트엔드가 `limit=40`을 요청하고,
백엔드가 다나와는 40개 이하·컴퓨존은 20개로 제한한 뒤 한 판매처 페이지만
읽었다. 브랜드·칩셋 필터는 그 작은 첫 페이지에서만 적용돼 결과가 더 줄었다.
이전 메인보드 화면은 CPU/RAM 호환 조건으로 제품을 추가로 제외했다.
GPU 시리즈 버튼은 모델 목록을 펼치기만 했고 시리즈 검색 조건을 전송하지 않았다.
따라서 결과 수만 늘리거나 클라이언트 슬라이스만 수정하는 것으로는 해결되지 않았다.

검증: `python3 -m unittest discover -s tests` 및
`node --test tests/test_builder*.js`. `test_product_browsing.py`는 실제 HTML 파서
경계에서 50개 페이지·추가 페이지·20행 오프셋·중복·시리즈/제조사/칩셋 조합을 확인한다.
